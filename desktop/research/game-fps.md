# 显示 FPS 与帧节奏

本文描述 2.8.0 起的显示统计口径；PC 2.9.0 增加可选自动授权，统计逻辑不变。使用步骤见 [电脑端说明](../README.md)；已替换的提交计数器保留在 [2.6.0 历史实现](game-fps-2.6-history.md)。

## 数据来源与范围

内嵌 MIT 授权的 PresentMon 2.6.0 原生分析源码，固定提交 `e13fce6acdb55a808fd8318175a56863e532d95f`，编译为随包 DLL，运行于既有授权采集进程。无需另装 PresentMon、RTSS、VC 运行时或新驱动；FPS 不依赖 PawnIO。源码适配和构建见 [集成说明](../PanelDeck.PresentMon/README.md)。

根据前台窗口客户区覆盖显示器识别独占 / 无边框全屏目标，不使用游戏名单。普通最大化窗口不算全屏，也不能仅凭窗口区分游戏和其他全屏程序。目标身份包含进程与创建时间；窗口或目标变化时重建统计。

统计成功且完成显示链分析的 `Presented` 事件中的 `Displayed` 时间戳，包含可追踪生成帧，排除 `Repeated`、失败、丢弃、丢失及其他进程 / 已知其他窗口。迟到生成帧按显示时间排序、去重，多交换链只选一条近期活跃链，不相加。

## 三个读数

| 指标 | 定义 |
| --- | --- |
| 显示 FPS | 约 2 秒窗口的显示帧间隔换算频率 |
| 平均帧时间 | 同一窗口的平均显示帧间隔，单位 ms |
| 1% Low · 30s | 最近 30 秒取最慢 `ceil(间隔数 × 1%)` 个间隔，先求平均耗时再换算 FPS |

1% Low 要求完整 30 秒历史且至少 100 个间隔。它不是帧时间第 99 百分位的倒数，也不是全局会话统计或应用原生帧统计。三项指标来自同一交换链；没有足够显示数据时为空，不回退到提交计数。

丢事件、缓冲溢出、目标切换、暂停、睡眠或显示间隔达到 3 秒后清空历史并重新预热。手机数据过期或断连也会清空界面读数。

## 开销控制

- 只在手机在线、面板亮屏且电脑未睡眠时续租采集；没有全屏目标时不持续跟踪。
- 仅启用显示与帧类型跟踪，关闭 GPU / GPU 视频、输入、PC 延迟、应用时间标记、外部测量和着色器编译分析。显示链仍需要系统内核与 DWM 事件，不能把全部事件限定为单个游戏 PID。
- ETW 每块缓冲 64 KiB，最少 16 / 最多 128 块，禁用按 CPU 分配，1 秒投递。丢事件、缓冲丢失或帧环溢出使当前统计失效。
- 最多 8 条交换链，每条环形缓冲最多 32768 个时间戳；复用一个排序缓冲，1% Low 至多每秒计算一次。极高帧率下容量无法覆盖完整 30 秒时不输出 1% Low。
- 复用授权进程、手机更新通道和亮屏租约；不录制 CSV / ETL，不加入悬浮层或高精度定时器。

## 验证与边界

已完成原生 / 托管合成测试、构建、真实手机链路，以及《007FirstLight》动态帧生成场景约 74 秒连续资源采样。曜屏两进程平均合计整机 CPU 为 0.0881%（16 逻辑处理器）；这是应用总占用，不能视作 FPS 的独立增量或游戏性能损失。测量条件、内存与证据见 [当前验证记录](../VALIDATION.md)。

显示时间来自系统事件，不是屏幕像素的光学测量。图形 API、驱动、合成路径及帧生成模式的覆盖仍需实测，尚未完成所有 DLSS 倍数验证，也不输出原生 / 生成帧分拆。未与 RTSS 或游戏内计数器校准，不能保证不同数据源、时间窗口和刷新频率的读数一致；同场景开启 / 关闭采集的游戏性能 A/B 也未完成。

更多指标及额外跟踪要求见 [PresentMon 指标说明](presentmon-metrics.md)。旧版提交计数与旧 CPU 测量不作为当前显示帧率的验收结论。
