## 2.9.1：自动完整采集实机验证

2026-10-24。在当前 Windows 管理员账户下实测。2.9.0 首次实际注册后发现 Windows 会省略任务 XML 中为 true 的默认项，原校验因此误判配置无效；2.9.1 按计划任务默认值解析，并增加省略默认项 / 显式禁用的回归用例。129 项 Windows 检查通过。

- 用户保存开关并确认 UAC 后，任务实际进入 Running，完整硬件数据恢复；没有使用主界面手动授权代替自动任务。
- 用户从托盘完整退出并用 Launcher 普通启动，旧主程序和旧采集进程均已消失。新任务运行时间随重启更新，新主程序与采集进程共两个，读数持续更新。
- 直接读取 Windows 进程令牌：主程序 TokenElevation=0，采集进程 TokenElevation=1，确认界面 / 网络服务未提升权限。
- 采样示例：CPU 62.75°C、54.06 W、风扇约 1484 RPM；这些是状态读数，不是性能开销测量。FPS 为“等待全屏游戏”，本轮未运行全屏游戏。
- 任务为当前用户 Interactive / Highest；用户只有任务读取与执行权限，受保护副本由 Administrators 拥有，普通 Users 仅可读 / 执行。普通登录启动指向现有发行目录，配对、端口和主题保留。

本地证据：`artifacts/automatic-collection-2.9.1-live.json`、`artifacts/automatic-collection-2.9.1-tokens.json`、`artifacts/automatic-task-2.9.1.xml`。实测版本为 `2.9.1+b4ee7d5`。程序重启由用户完成，未重启或注销 Windows；真正重新登录、关闭开关移除任务、游戏场景与长期稳定性仍未实测。

## 2.8.0：历史帧率验收与资源采样

以下为 2026-10-07 的测量，未用于声明 2.9.0 的实际资源占用。

### 构建、统计与界面

2026-10-07。PC 精简包和手机 APK 均已安装并启动 2.8.0（versionCode 15），用户已重新完成 UAC，手机服务 `connected=true`、`panelResumed=true`。两项读数复用原 PresentMon 显示时间戳、授权进程及数据通道，无新增事件提供程序、进程或前端定时器。

- Windows 测试通过：平均显示间隔、完整 30 秒预热、最慢 ceil(1%) 间隔平均耗时倒数、旧卡顿滑出窗口、多交换链、过期/恢复、迟到生成帧、环形缓存回绕及容量不足时拒绝输出 1% Low；三个指标的管道往返与暂停清空也已验证。
- .NET 发布与 Android 构建/lint 通过；前端验证正常、统计中、旧 PC、断连与数据过期时的三个读数。九主题 596 项渲染检查、136 项主题检查、70 项预览检查通过。
- 已目视检查九主题截图及窄横屏：主 FPS 保持较大字号，辅助读数 44px / 主数 76px；短横屏为 34px / 64px。保留原配色、圆角、时钟和硬件布局，纸页窄横屏仅增加 FPS 卡内部空间。示例截图均为合成数据，位于 `artifacts/ui-2.8.0/`。
- 空闲时真实手机正确显示三个缺失占位；后续游戏实测已确认 FPS、帧时间和 1% Low 经真实局域网链路显示。空闲截图 `artifacts/phone-fps-2.8.0-idle.png` 仅用于缺失状态验收，游戏采样见下文。

统计定义与资源上限见 [帧率实现说明](research/game-fps.md)。1% Low 是滚动 30 秒显示帧口径，不是全局会话统计、应用原生帧统计或帧时间第 99 百分位的倒数。

### 实机资源采样（2026-10-07）

用户运行 `007FirstLight`，明确开启动态帧生成（未指定倍数）。未切换游戏窗口、调整设置、关闭采集或请求重新授权。通过 Win32_Process 累计用户态/内核态 CPU 时间、内存计数和现有快照接口约每 2 秒采样，共 95.57 秒。前段包含非全屏及建立统计窗口的状态，资源结论采用最后连续有游戏读数的 74.28 秒、36 个样本。

| 进程 | 平均整机 CPU（16 逻辑处理器） | 末次工作集 | 末次私有提交 |
| --- | ---: | ---: | ---: |
| 主程序 | 0.0145% | 163.42 MiB | 88.21 MiB |
| 授权采集 | 0.0736% | 127.10 MiB | 101.11 MiB |
| 合计 | 0.0881% | 290.52 MiB | 189.31 MiB |

约 2 秒区间的最高合计 CPU 为 0.1846%，不是瞬时尖峰。连续片段内主程序私有提交增加 1.82 MiB、采集进程减少 0.13 MiB；时长不足以判断长期泄漏。工作集可能包含共享页面，不等于独占物理内存。快照最大数据年龄 2334 ms；1% Low 在建立 30 秒历史后开始输出，22 个采样点有值。

结论仅支持当前场景下曜屏自身 CPU 占用低。这是硬件采集、显示帧统计、界面及局域网服务的总占用，不能分离 FPS 功能的独立增量，也不涵盖计入游戏/系统进程的 ETW 事件生产开销。动态帧生成及场景变化期间显示 FPS 范围约 46–250，未做关闭采集的同场景对照，不据此判断游戏掉帧比例或帧生成计数精度。

证据：`artifacts/performance-2.8.0-game.json`、`artifacts/measure-performance-2.8.0.ps1`、`artifacts/phone-performance-2.8.0.png`。诊断脚本的 CPU 不包含在曜屏进程合计中；手机截图只证明真实链路显示，不构成第三方计数器校准。

### 帧率与运行环境的未验证项

- 所有图形 API、驱动、游戏和 DLSS 帧生成模式的兼容性，以及与参考计数器的校准。
- 同一游戏场景开启 / 关闭采集的帧时间 A/B；当前进程 CPU 数据不能回答游戏损失多少性能。
- 长时间稳定性与内存泄漏；当前资源采样不足两分钟。
- 干净 Windows 环境中从缺少运行时到安装完成的端到端验证。
